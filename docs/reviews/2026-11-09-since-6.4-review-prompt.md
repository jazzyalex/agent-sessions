## The product

Agent Sessions is a macOS app (Swift, SwiftUI plus AppKit tables). It indexes the local session
logs of 17 coding agents (Codex, Claude Code, OpenCode, Cursor, Gemini and others) and lets the
user browse, search and resume them. It is a history browser, not a chat client, but a live
session's transcript does update while the agent runs. Deployment target: macOS 14. macOS 26
has its own session-list toolbar layout.

## What changed (intent, as the authors state it)

Skip docs-only commits (`docs(...)`, `chore(release)`). The code changes fall into five groups.

**A. Message origin** (`55aec3c4`). Message blocks are labeled by their real origin. Only text
the user typed is "You"; injected context (instructions, environment, skill files) is hidden
unless a setting is on; notifications, peer messages, commands and scheduled prompts get their
own labels. Main files: `Model/MessageOrigin.swift`, `Services/MessageOriginClassifier.swift`,
`Services/ClaudeSessionParser.swift`, `Services/SessionTranscriptBuilder.swift`,
`Services/SessionIndexer.swift`, `Views/TranscriptOriginLineCell.swift`,
`Views/TranscriptBlockListView.swift`. Spec:
`docs/superpowers/specs/2026-11-07-transcript-message-readability-design.md`.

**B. Hide tool work** (`508e9ac2`). The Session view reads as prompt and answer. Tool calls
(failed ones too) and the agent's working notes between them sit behind the Tools chip, which is
off by default through a one-time migration. A turn's answer is its last agent text. Find still
counts matches in hidden rows; an explicit Find step turns Tools on for that session without
saving it. Errors covers only error blocks outside tool calls. The harness-context toggle moved
to Settings. The transcript role chips have three width densities. Main files:
`Services/SessionRoleFilters.swift`, `Services/TranscriptTurns.swift`,
`Services/TranscriptDerivedState.swift`, `Services/TranscriptTurnTiming.swift`,
`Services/TranscriptFindNavigator.swift`, `ToolRendering/TranscriptToolRows.swift`,
`Views/TranscriptBlockListView.swift`, `Views/TranscriptPlainView.swift`, the two Preferences
files. Spec: `docs/superpowers/specs/2026-11-08-transcript-hide-tool-work-design.md`. Its §0 is
binding and overrides the later sections where they differ.

**C. Codex titles** (`f0e52529`, merge `cca27e07`, `270960f5`). Readable titles from long or
wrapped Codex prompts. Files: `Telemetry/SessionInfoQuickFacts.swift`,
`Views/UnifiedSessionsView.swift`.

**D. macOS 26 session-list toolbar** (`ea44aeaf`, `20a1bbbb`, `025f3cbb`, `cd50564a`). On
macOS 26 the list controls form one leading group that ends at the list/transcript divider and
fold into menus in three tiers as the pane narrows. macOS 15 and earlier keep the old layout.
File:
`Views/UnifiedSessionsView.swift` (`SessionListToolbarRow`).

**E. Prices and format drift** (`06159578`, `f133cc71`, `533a1486`). A new Copilot model price,
manifest sequence `2026110801`, and redacted fixture records for new log records that must not
render as messages. Files: `CodexStatus/RunwayPriceTable.swift`, `docs/prices-v2.json`,
`Resources/Fixtures/`, parser tests.

## Where to look hardest

These are the seams where groups meet. They are areas to examine, not known bugs.

1. **Origin → turns → visibility (A with B).** Origin decides the role of a block; B decides
   turns, answers, notes and what each chip shows. Check every origin kind: can injected context,
   a placeholder or a peer message start a turn, become a turn's answer, or count as a note? Does
   a hidden block ever split a tool run or a message group?
2. **Row identity and index math.** `TranscriptToolRows.emit`, message groups, windowed loading
   ("load older"), live appends and filter changes all produce or reuse row ids. Look for
   crashes (empty arrays, out-of-range indices), duplicate ids, and rows that jump or lose
   selection after a filter change, a live append or a window shift.
3. **Find, jumps and counts.** For each chip combination, do the chip counts, the ▲▼ stops,
   ⌘G / ⇧⌘G and Find's match count agree with what the user can see? Find counts hidden
   matches by design. A Find step may turn Tools on for the session but must not save it. Check
   the Errors chip with Tools off.
4. **Saved settings and migration.** The Tools-off migration must run once and must not undo a
   later choice. Check the saved role-filter format, the `SessionShowContext` default, and what a
   6.4 user sees on first launch of this build.
5. **Main-thread cost.** Filter changes and live updates reload AppKit tables. Look for work
   that scales with the whole session on every keystroke, live append or scroll, on sessions with
   10,000+ blocks. Derived state should be computed once and reused.
6. **Two toolbars, two OS versions (B with D).** The session-list toolbar (D) and the transcript
   toolbar (B) both adapt to width. Check narrow and wide windows on macOS 26 and confirm that the
   macOS 14–15 path did not change.
7. **Titles (C with A).** Title extraction must not turn injected instructions into a title and
   must not drop a real prompt.
8. **Localization.** Every new user-visible string needs a catalog key with zh-Hans. The
   validator pins the key count and a SHA of the key set.
9. **Prices.** The manifest sequence rule and the released-fingerprint rule in
   `docs/prices-v2.released.json`.

## Known and accepted

Do not report these unless the real effect is worse than stated here:

- In a live session with Tools off, each new agent message reloads the whole transcript table,
  which clears a selection that spans blocks.
- Typing in Find does not jump to a match that is only in hidden rows. It counts the match and
  jumps on Enter or ⌘G.
- At the narrowest transcript widths the hover ▲▼ arrows on role chips are gone; ⌘G / ⇧⌘G
  still step.
- zh-Hans wording quality. A native check is planned separately.
