# October 2026

- OpenCode native shared-service IDs identify working sessions across terminals and Desktop. The app bundles and automatically manages a TUI drop-in for exact selected working/idle sessions, preserving configuration and other plugins, supporting custom roots, and showing setup status in Preferences. Desktop idle selection remains unsupported by OpenCode 2.1.2.

- OpenCode new-session monitoring now watches its database and WAL; native session IDs prevent duplicate titles and closed same-folder conversations from receiving the live indicator.

- Codex quota checks now retry temporary failures within one minute while visible, with an immediate Retry action and a warning explaining how to recover. Fallback readings no longer clear weekly burn calibration or replace recovered live usage; server rate-limit waits are preserved.

- Fixed startup placeholder overlap by hiding the mounted transcript host when there is no selection; indexing subtitles now omit completed launch phases.

- Read-path hardening: fx refresh keeps last-known rows for discovered but temporarily unreadable files, failed full parses no longer poison reload gating, and schema-4 exact lightweight counts are cached per size/mtime revision.
- OpenClaw stores a SHA-256 preview-window digest as a nullable additive `session_meta.openclaw_preview_digest` field, checks it before any cold indexed-metadata reuse, and uses database/WAL fingerprint plus session extent to skip hashes for unchanged stores.
- Claude's path-scoped request-log migration now uses a v2 marker even after v1, verifies parsed top-level JSONL markers through EOF before deleting rows, and separately retries pending image-cache removals during later ingest passes.

- Session Info now opens for every registered agent source, showing provider-neutral metadata immediately and source-appropriate detailed telemetry when the local records support it.
- Session list startup now shows an explicit indexing or update state while the first
  provider results settle; filtered, failed, and genuinely empty results have distinct copy.
- Detailed Session Info telemetry now has a five-second cancellation-aware timeout and
  explicit retryable timeout copy, so quick info remains usable during slow scans.
- Provider metadata is now sanitized at presentation time: prompt/XML payloads are not shown
  as models or titles, and unsafe values are reported as ambiguous rather than rewritten.
- Unified provider refreshes now use a cancellation-aware two-source budget and keep the
  Session list visibly indexing while additional enabled providers wait to run; the
  mixed-provider stress baseline remains open.
- Live presence discovery now keeps vetted headless Codex and OpenCode CLI runs even when they have no TTY, without admitting app-bundle processes or changing Codex Desktop handling. OpenCode exact identity is supported when the process exposes a per-session `ses_*.json` file; no OpenCode token telemetry or exact SQLite `opencode.db` current-session inference was added.
- Hardened the stage0 baseline rebuild path for OpenCode's current SQLite storage. Declared `opencode_latest_session` mode now fails closed when `db_roots` is absent instead of silently sweeping legacy JSON or accessing the weekly monitor's implicit HOME DB default.
- Configured databases remain bounded latest-session diagnostics. Parsed-row limit checks are conservative, and DB-backed runs always return nonzero and refuse `--emit` before any fixture write; file-backed all-session rebuild behavior is unchanged.
- Session Info now separates immediate provider-neutral metadata from optional detailed telemetry, so all registered agents can show current model/configuration context without waiting for a full transcript scan.
- Detailed Session Info telemetry now uses the source registry for Antigravity planner token records and Kimi per-turn usage, while Grok exposes model and reasoning-effort history and states that token counts are not recorded. Kimi session-level summaries are used only when per-turn rows are absent.
- Cline Session Info now reads assistant model history and per-message input, cache-read, cache-write, and output components from its manifest+messages pair; provider-specific pricing and quota remain unavailable.
- Droid Session Info now reads the current model and reasoning effort from the matching settings snapshot; aggregate Factory token evidence is not assigned to a model or ownership class, and malformed or ambiguous usage is labeled unavailable.
- DeepSeek Harness Session Info now reads v4 request/model history and assistant-message token components through the registry, verifies repeated stream usage without double-counting, and fails closed on inconsistent usage; cost and quota remain unavailable.
- Cursor Session Info now uses its registry reader for current model metadata while keeping first-observed history, token, cost, and quota fields honest about the source format's limits.
- Qwen Code Session Info now reads active-branch assistant usage and model history through the registry, excludes rewound branches and duplicate UI telemetry, and labels cost and quota as unavailable.
- Devin Session Info now reads the current model from the shared SQLite session row through the registry, keeps metadata provenance unanchored, and leaves per-turn history, tokens, cost, and quota unavailable under the audited store contract.
- Session Info now reads fx's audited aggregate input/output totals and current model/effort from `session.json` through the source registry; per-turn/cache attribution, cost, and quota remain explicitly unavailable.
- Crash diagnostics now suppress the same report after `Later`, filter XCTest-injected test-host reports, and use stable POSIX descriptor freshness checks so failed telemetry reads return unavailable instead of aborting.
- Session Info now emits opt-in process-local performance snapshots for controlled smoke tests. The final all-provider run observed model-first-paint averaging 58.6 ms across 2 paints, one 5,396.9 ms telemetry scan of 5,570,560 bytes, zero cache/coalescing/duplicate-parse hits, and 2 transcript/telemetry overlaps; this is a one-run baseline, not a release benchmark.
- Follow-up cold-start samples (three launches each) measured Codex at 95.2/116.5 ms model-first-paint p50/p95 and 5,211.7/5,328.8 ms telemetry p50/p95, OpenCode at 12.0/12.0 ms and 26.3/28.5 ms, and Claude at 13.0/22.4 ms and 1,099.0/1,106.1 ms. All nine runs had zero cache, in-flight-join, and duplicate-parse hits; p95 is the maximum because n=3.
