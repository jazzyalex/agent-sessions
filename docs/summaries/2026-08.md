# August 2026

- The weekly calibration stopped keying its cache on a moving target. `UsageResetText.resetDate` resolves Claude's tmux `/usage` relative reset text ("in 4h 28m") against `now`, which is right for a displayed countdown and wrong for a window identity: polled minutes apart it drifts past the 120s anchor-equality tolerance, so `ensureBootstrap` wrote a new `quotaMeter.weeklyBootstrap.claude.unscoped.<epoch>` key every poll — ten accumulated in 90 minutes on the development machine, unbounded growth in the preference domain. Worse, each held a measurement built from the FIVE-HOUR window's percent over a week of priced activity: 50pp/$1282 = 0.0394 pp/$ against the account's real 0.0625, 37% low, and every one of them eligible to win the carry-over slot. They lost only because 50 < 77. The new `resetAnchorDate` refuses relative text and is used by both providers' calibration gates; `resetDate` is unchanged for display. Found by dumping the live preference domain rather than by review — three static review passes over this subsystem did not surface it, and the giveaway was a constant +4h28m offset between each record's scan time and its anchor. The eight bogus keys were deleted by hand; a first pass at identifying them by "anchor less than 24h after the scan" would also have deleted the two genuine 77pp records, which were simply scanned six hours before their window closed.
- Session Runway gained a weekly quota unit (`Wk`, percentage points per hour per session). The model is `calibration = quota percentage points / priced API-equivalent activity`, applied to each session's own current $/h, so the reading responds to that session's activity instead of redistributing one account rate. The calibration is bootstrapped from transcripts already on disk — Codex `token_count` lines carry `rate_limits` on the same line, making a transcript a full quota trace; Claude's carry none, so its window is priced from token accounting and divided by the reported percent. Both providers quantize weekly percent to whole points (Claude's OAuth `utilization` returns `27.0`/`11.0` and `limits[].percent` is a literal integer), so the numerator uses the quantization midpoint. An external review of the shipped code found three cache defects, all reproduced against live state before being accepted. First and worst: restore consulted only the carry-over slot and the current anchor's cache, so a completed window's measurement sat on disk unread — a Claude week measured at 77pp/$1239.62 (0.0621 pp/$) was passed over for the fresh window's 7pp/$142.71 (0.0491 pp/$), understating every Claude session by 21%; every stored window is now swept once per process and the largest numerator wins, which corrected the live account on relaunch. Second, anchors were marked on scan dispatch and no failure path cleared them, so one unreadable root retired that refresh bucket for the window, with a startup dead zone where a rejected 0pp scan blocked retries until 3pp; anchors now record successes only and failures back off ten minutes. Third, freshening paired the current reported percent with a carried-over window's dollars, which belongs to neither window; it now requires the anchors to match. Rescans also trigger on age, because the ledger can only extend a denominator inside its 6h retention. A fourth review finding — that Claude's percentage is exact and wrongly receives the integer midpoint — was rejected against the live payload above. The spec's claim that two Claude windows agreed "within quantization" was withdrawn: they differ by 26% and the disagreement is unexplained. Cross-provider, Codex consumes roughly 3.6-4.0x more weekly quota per API-equivalent dollar than Claude; the spread is the quantization policy (dividing floors gives 3.61x, applying this model's own midpoint to both gives 4.03x, and the app serves the midpoint), and it is a snapshot rather than a constant because the Codex numerator is only 4pp and carries plus or minus 12% from quantization alone. The direction is not a cache-mix artifact (both windows ran 93-98% cache reads) but does rest on the unverified assumption that quota tracks API list price. A second review pass then found three more scope defects, all fixed: an in-flight scan could land in the wrong account after a switch (results now carry a scope generation captured at dispatch), migration ignored price revision and limit shape so a stale plan could hold the carry-over slot forever (bootstraps are now stamped and incompatible ones are skipped, while unstamped legacy records stay usable), and the scope-switch path called `restored.remove(provider)` against a set holding full defaults keys, which removed nothing and left an earlier account's persisted samples unread after A to B to A. The same pass corrected the midpoint's home: it lived only on the freshening path, so a carried-over measurement served the raw floor while a current-window one served the midpoint, making two providers' numbers incomparable by accident. Claude's `observeQuota` call also stopped claiming `hasExactPercent: true`, which had lowered its acceptance floor to 0.25pp on a source whose real quantum is a whole point.
- Claude's model-scoped weekly window is decoded and surfaced. The account's usage response carries a `limits` array — `session`, `weekly_all` and `weekly_scoped` entries, the last naming a model in `scope.model.display_name` — while the legacy `seven_day_opus` and `seven_day_sonnet` keys are both null, so on a current account the array is the only place the scoped window appears. `ClaudeUsageNormalizer` picks the scoped entry (the server's `is_active` flag wins, otherwise the most consumed window), feeds the existing single scoped slot, and carries the model name through to the view layer; the legacy key remains the fallback for older payloads. The compact Quota Meter is untouched by owner ruling — its fixed 53pt `Wk` column always shows the all-models figure — and the named line lives in the menu-bar dropdown beside the existing 5h and Wk reset lines, which is the surface that has the room. Decoding is deliberately tolerant: the same payload ships a dozen codenamed experiment keys and unknown `kind`/`scope` values must degrade to "no scoped window" rather than failing the whole fetch, which nine tests pin against a captured live payload shape.
- Corrected the support matrix for Qwen Code and Kimi Code, which listed "usage/rate-limit tracking" as an unsupported surface in a way that read as "the agent does not publish this data". Neither publishes a quota or limit endpoint, but both write per-call token accounting into every session — Qwen in `systemPayload.uiEvent`, Kimi in `token_counting.measured`/`turn_recorded` — and Agent Sessions does not yet read it. The entries now separate the two claims. Pi and Grok CLI were left alone: there is no evidence either way for them.
- Droid's `defaultEnabled` moved from `.always` to `.whenAvailable` on an owner ruling: it is not a supported source and will not be until a steward takes it on, so it must not be enabled for users who do not run it. The affected population was narrow and specific — `seedIfNeeded` writes every source's enablement key from availability on first run, so only installs seeded *before* Droid joined the registry ever reached the `.always` default, leaving upgraders as the one cohort with Droid silently on. Explicit user choices are untouched; `isEnabled` reads a stored preference before consulting the default. The `.always` was never a product call, only a mirror of pre-refactor runtime behavior (K7), and four tests pinning that cohort were updated, including a rewritten dedicated test carrying the ruling. Droid's Settings pane stays out of the sidebar for the same reason; it keeps its on/off row in General, which is built from the whole registry.
- Analytics, first-run setup and Settings now take their per-agent enabled defaults from `AgentEnablement.isEnabled` instead of literals of their own. Hermes and Cursor were hardcoded on and OpenClaw hardcoded off in those three views, but all three are availability-defaulted sources, so on an install where the key had never been written the views disagreed with the main window in both directions — an installed OpenClaw could be counted in the session list and excluded from Analytics, which gates its per-source rows on exactly these values. Folded into the same pass: the Qwen and Fx indexers snapshot their discovery object before the detached scan the way Antigravity now does, three same-key double reads in `PresenceEngine` were deleted, and the uncalled `AvailabilityContext.live()` is fenced `@available(*, unavailable)` so its uncached PATH sweep cannot be adopted on a hot path.
- Copilot session titles are read out of `workspace.yaml` block scalars. Copilot writes a multi-line title as `name: |-` with the text on the following indented lines, and the parser took the value on the `name:` line itself, so eight of the twelve Copilot sessions on the development machine were listed under the title `|-`. Quoted and single-line titles are unchanged, a value that is only a block indicator now reads as no title, and the guard restricting `workspace.yaml` to the per-session directory layout still holds.
- The Antigravity sessions-root override now reaches the indexer. It was already honoured by availability, presence and archive backfill, but the indexer built its discovery with no arguments and always scanned the default root, so a custom path left the agent looking available while listing nothing. A changed preference is picked up on the next refresh rather than the next launch. The override moves the markdown brain directory only — CLI transcripts continue to come from `~/.gemini/antigravity-cli/brain`, which the Settings copy now states.
- Weekly Session Runway now attributes a recent same-reset quota tick instead of the full-window historical average, falling back to token throughput until the provider emits enough data. Its calibration now invalidates in-memory state on account, price-table or limit-shape changes, and stale scan failures cannot cool down a replacement scope. The API-equivalent price table carries current GPT-5.6 Sol, Terra and Luna rates plus Claude Sonnet 5's permanent lower price; token and 5h calculations are unchanged.

OpenCode fails at 95.8% from externally supplied disk measurements ([discussion #54](https://github.com/jazzyalex/agent-sessions/discussions/54), receipt in `scripts/session_bench/`); Grok tool-call folding is disqualified because its prefix property holds for only 66% of tool-call groups, Codex's freelist waste sits outside its session store and scores not_run, as does every source with no qualifying rule.
- Pi, Kimi Code, Qwen Code and Grok CLI resume correctly when the app is launched from Finder. The first three ship as `#!/usr/bin/env node` scripts, so the Finder-inherited PATH could not resolve their interpreter and the failed probe was recorded as a CLI with no resume flags — a verdict that was then cached and never re-checked. Probes now run with the PATH reported by the login shell, a probe that never executed is a failure carrying its real stderr, and a cached binary advertising no capabilities is discarded and re-probed. Grok CLI is on the same helper: its binary is native rather than a Node script, so the interpreter failure never applied to it, but it probed under the same PATH and cached the same dead verdict.
