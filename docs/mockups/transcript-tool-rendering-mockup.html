Today the view prints all of it raw. The proposal pairs each call with its output, splits the script into its commands, and decodes every layer.

What goes wrong
  1. "10 tool calls" counts blocks. Five calls, each with an output block, give 10. The five calls run six actions. (Your screenshot: 6 calls, so "12 tool calls".)
  2. The call line is the tool name plus the input squeezed onto one line and cut at 120 characters. You cannot see the full command anywhere in the card.
  3. The output is labelled "Tool call" because the output event has no tool name, and nothing ties it to its call.
  4. The parser turned the output array into pretty JSON at index time, so escaped \n, \" and \\\" appear as text. That is three layers of escaping.
  5. The 20-line limit counts \n characters. One escaped line holds the whole output, so a "1-line" output wraps to a wall of text.
  6. Text mode, search and export already run a 1,700-line tool normalizer. The Session view does not use it.

What changes
  • One row per action. The script's two commands become two rows, and each row owns its own output.
  • Each row reads as a sentence: verb, object, result. Read-only commands such as sed -n, nl, cat and rg read as Read and Searched. The exact command is always one click away.
  • Success is quiet and failure is loud. The failed run opens itself and shows the red count in the header.
  • Agent truncation goes to the footer as a fact. It is not printed as text inside the output.
  • Long output shows its first and last lines with a fold between them. Long lines get a character limit.

Three levels of detail

A run of tool calls is one card. Level 0 is a one-line summary. Level 1 lists the actions. Level 2 shows one action in full. Each level answers a question that gets less frequent: what happened, which steps, show me the bytes.

Each case comes from real local sessions (see the spec's corpus section). Rule: always show the call, even when the output is missing, and always show the output, even when the call is missing.

Interrupted means a turn_aborted or interrupt event came after the call. No result recorded means the session ended, or is still running, with no output for the call. Orphan output means the windowed view cut off the call. Pairing runs over the whole session, so the row still knows the tool name. Rejected calls show in grey (today they are hidden). Encrypted Codex collaboration messages show a placeholder, never the ciphertext.
