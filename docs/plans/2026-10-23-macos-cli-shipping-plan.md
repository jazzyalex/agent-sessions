# macOS CLI first, terminal UI second

Product status (2026-10-24): on hold pending validation. See [the product evaluation](2026-10-24-cli-product-evaluation.md); its product rationale and phase order supersede this document's. The architecture contracts below remain reference.

Status: PLAN READY after focused Repo MCP Pro confirmation on 2026-10-23. Both remaining findings are closed for planning. No implementation or release is authorized; owner approval is still required before coding.

## Outcome and scope

Ship `agent-sessions` as a command-line companion to the native Mac app. Its first job is letting a coding agent find previous work and retrieve attributable excerpts. A human can use the same commands from a shell. Ship an interactive TUI in phase two, using the CLI contract rather than another parser implementation.

Proposed first supported sources: Codex, Claude Code and OpenCode on macOS 14+, on Apple Silicon and Intel. This is an explicit initial product scope, not a feature flag: the first CLI's `sources` reports only its supported sources. All existing Mac app sources and behavior remain supported. More CLI sources require the same lifecycle qualification, rather than inheriting a support claim from a parser fixture. Linux build compatibility remains desirable, but Linux distribution and real-install qualification do not block the Mac release. Native Windows, WSL qualification, a daemon, a new MCP server, remote aggregation, quota/runway UI, and transcript mutation are outside phase one.

Decision rationale: the proposal already shares Swift parsing and a JSON process boundary; the owner's September 29 direction prioritizes agent retrieval. Issue #80 independently requests CLI access for coding agents. These establish a coherent use case, not a measured adoption forecast. Evidence: [PR #77 discussion](https://github.com/jazzyalex/agent-sessions/pull/77#issuecomment-5899242742), [issue #80](https://github.com/jazzyalex/agent-sessions/issues/80).

## Review findings and disposition

### 1. Port the seams onto current main; do not restore the September implementations

The parser move in #77 extracts about 1,200 lines from SessionIndexer. Current main has since added compressed Codex reads, thread/surface work and other parser changes. The package source list does not contain CodexRolloutStorage.swift or its newer decoder dependencies. OpenCodeSqliteReader and OpenClawSessionDiscovery have also changed substantially. Reuse the extraction pattern, not the old parser bodies or old source lists.

Evidence: `4b546dcc:Package.swift:8-111`; current `AgentSessions/Utilities/CodexRolloutStorage.swift:8-19,38-49,100-121`; current `AgentSessions/Model/OpenClawSourceDescriptor.swift:25-41,67-72`. Current main commits include `3a3bd27b` (compressed Codex), `c4e21e01` (OpenCode 2.x), `cb13a206` (OpenClaw SQLite), `c843cd59`/`81b9b921` (Claude request-log exclusion and repair), `9f87e07f` (dated pricing), and `db5474a9` (Sendable warnings).

Disposition: rebuild CodexSessionParser from the current SessionIndexer implementation, keep existing forwarders and DEBUG counters, and preserve current format tests. Rebuild the manifest from current dependencies. Preserve current Cursor ACP handling even though Cursor is outside initial CLI support. Do not bring the old bare-tier pricing aliases into the extraction.

### 2. Shared parsing alone leaves incorrect refresh and deletion behavior

#77's runIndex constructs physical file refs directly, creates identity authority only for a nonempty database list, and does not pass live-path authority. It can leave a removed final session indexed; Cline companion-only changes and DSH selected-generation changes bypass the intended revisions. A failed enumeration is also collapsed to an array without status.

Evidence: `4b546dcc:cli/as-core/Commands.swift:188-235` (same logic at companion `Commands.swift:278-324`), `4b546dcc:cli/as-core/Drivers.swift:17-25`. Main already distinguishes unknown from authoritative empty: `AgentSessions/Search/SearchIngestService.swift:15-58`; the app carries that proof into ingest at `AgentSessions/Services/UnifiedSessionIndexer.swift:1885-1919`. The app's revision mapping is at `UnifiedSessionIndexer.swift:2126-2166`.

Disposition: extract a shared Foundation-only refresh input/result and pure refresh planner, including completion status, scoped authority, resolved paths, per-session logical/artifact/content revisions, and diagnostics. Both hosts consume the same mapping/policy with explicit host configuration. Keep app UI scheduling, archive fallback selection and progress publication in its adapter. A partial/failed scan can retain confirmed rows and index safe updates, but cannot infer deletion authority over the failed scope. An authoritative empty set must still reach reconciliation. Cover legacy-file-to-database transitions and custom-root changes without retiring another root's rows. Do not put the whole app IndexDB/SearchIngestService into the CLI: use a small, separately owned CLI cache store with the schema and host boundaries below.

### 3. The companion read contract is useful, but needs source-aware target validation

Retain the final companion's pagination, UTF-8 truncation, event IDs/indices, supplied-ID equality check, untrusted-history label and no-index-write property. Its direct fileExists/isReadable preflight would reject a canonical Codex `.jsonl` path whose only physical file is `.jsonl.zst`. That is a concrete incompatibility when ported to current main. Also select identity parsing per storage URL, not merely because the provider has any database parser.

Evidence: `4c51ca4d:cli/as-core/Commands.swift:113-126,185-211`; `4c51ca4d:cli/as-core/Drivers.swift:40-44`; current `CodexRolloutStorage.swift:8-14,38-49,100-121`; current OpenClaw descriptor declares both path and identity parsers at `Model/OpenClawSourceDescriptor.swift:67-72`.

Disposition: resolve source storage before readability checks. Preserve logical source/path/id in results while reading the selected physical artifact. Require an identity for database URLs; for path URLs parse by path and validate a supplied ID. Tests must cover compressed-only canonical Codex paths, both physical forms, restore-to-plain, unreadable/truncated compressed input, and hybrid file/database dispatch.

### 4. Error, output and freshness contracts need completion before release

runIndex catches each source error, emits a record and exits successfully. indexedRows uses try? and silently substitutes an empty array for a database error. list/search open and potentially create the index. Search returns whole session metadata without evidence snippets or a pagination cursor. Its query uses the existing bounded sampled FTS index, which does not prove absence from the full transcript.

Evidence: `4b546dcc:cli/as-core/Commands.swift:215-232,313-362`; companion `Commands.swift:298-324,404-454`; `4c51ca4d:docs/cli-history-retrieval.md:84-92`. `4b546dcc:cli/as-core/Output.swift:17-26` silently emits `{}` on JSON serialization failure; replace this with an explicit failure.

Disposition: define stable JSON error and terminal-summary records; exit 0 for a completed query including no matches, 1 for source/runtime/partial failure, 2 for usage, and normal SIGINT behavior. Emit per-source status and aggregate status; preserve useful partial output but never label it complete. Add build/version/schema info. Read-only queries must not create or migrate an absent cache. Results identify index time and freshness/coverage; a stale cache is explicit. Use project/source/date filters and bounded evidence snippets for search; disclose sampled coverage and that no match is inconclusive. Indexing is always an explicit command.

### 5. Existing tests are a starting point, not present-main qualification

#77's changed XCTest files add two registry tests and three pricing tests; a test-name inventory against its original base finds no removed test functions in either file (20 to 22 and 20 to 23 respectively). Its golden script checks summaries, not full transcript equivalence, and DSH collection explicitly stops at v3. The final companion script has 13 test methods, including the later file-ID mismatch case; do not retain the older comment's count of 12 as the final inventory.

Evidence: `4b546dcc:scripts/as_core_contract.py:39-50,86-102`; `4c51ca4d:scripts/as_core_read_contract.py:47-195`; `.github/workflows/as-core-read.yml` in the companion adds macOS/Linux build-and-contract jobs. The PR's old green test claims were not rerun here. New fixtures and current lifecycle behavior need new qualification.

Disposition: preserve every current app test name; explain any intentional future removal. Add full event/identity parity checks, updated fixture inventory including DSH v4, and lifecycle tests independent of parser summaries. A passing golden generated by the CLI itself is not independent proof of fidelity.

### 6. Keep stats/cost work outside phase one

#77 builds usage accumulators, RunwayPriceTable and WeeklyQuotaCalibration provenance into the executable and maintains a second usage table. That is not necessary for history retrieval. Current descriptors also contain telemetry factories, scans and revision hooks absent from the proposal's base, so a mechanical UI split is insufficient.

Evidence: `4b546dcc:cli/as-core/Stats.swift:11-12,79-103`; `4b546dcc:Package.swift:99-104,130-139`; current `Model/SessionSourceDescriptor.swift:272-289`; `CodexStatus/RunwayPriceTable.swift:260,343-344,732-755` and commit `9f87e07f`.

Disposition: phase one does not ship stats, usage sorting, pricing aliases or quota extraction. Keep the existing Mac telemetry subsystem behavior and its descriptor/adapter wiring intact. Pure metadata needed by Session may remain in the core; the new three-reader core catalog excludes app telemetry factories/scanners rather than linking the full descriptor graph. Revisit stats only through the current telemetry API after history retrieval ships.

### 7. Strict parser completion and ingest reporting are prerequisites

The architect found that current Codex's public full parser discards its internal readSucceeded flag; a failed read can return a Session containing a synthetic error event. Claude's reader can end on an I/O failure, and OpenCode v1 loops lack the stronger SQL completion checks already present in v2. Ingest also collapses write failure into parseFailed and does not expose its full failure state through Progress. A command-level error envelope cannot repair that lost information.

Evidence: current `Services/SessionIndexer.swift:2337-2343,2445-2449,2490-2495`; `Utilities/JSONLReader.swift:10-19,182-194`; `OpenCode/OpenCodeSqliteReader.swift:1209-1247,1378-1396`; `Search/SearchIngestService.swift:102-119,795-816`. These are current-main integration issues to solve for the new strict CLI path, not a claim that all historical app displays were corrupt.

Disposition: introduce a strict ParseOutcome carrying complete/partial/failed/cancelled status, normalized session, diagnostics, relevant input revision and consumed byte/record/event counters. Recognized provider filtering is distinct from malformed records and I/O/decode/SQL failures. A historical error recorded by an agent is content; a reader failure is infrastructure status. Legacy app wrappers may retain their existing partial-display presentation while using the same strict reader result internally. Read publishes no successful page for incomplete infrastructure reads. RefreshReport separately records discovery, parsing, storage and reconciliation outcomes; partial index attempts preserve confirmed updates, return nonzero, and do not advance the last successful refresh marker.

### 8. The shared core must not mutate app-owned auxiliary caches

Current SearchIngestService creates ImageBrowserIndexCache by default and runs the Claude request-log reindex migration with it. The default cache points into the app's ImageBrowser directory, and invalidation removes files. A separate SQLite index alone therefore does not isolate the CLI. Evidence: `Search/SearchIngestService.swift:203-230,274-287`; `Utilities/ImageBrowserIndexCache.swift:53-58,319-325`; `Indexing/DB.swift:3635-3659`.

Disposition: share strict readers, models, text-building and refresh policy, not app-owned side effects. Keep the app's image-cache migration, archive mutation/invalidation and runtime wiring behind its host adapter. The CLI uses an inert app-cache policy, its own store, and Codex text-stream decoding; it must not invoke the writable random-access materialization facility at `Utilities/CodexRolloutStorage.swift:237-273`. Test app index, ImageBrowser cache, preferences and provider histories for unintended changes.

## Resolved architecture contracts

These decisions supersede the underspecified parts of the submitted draft. They address architect findings 1-7 without migrating the GUI database.

**Core boundary.** Create a small headless library of current models, strict source readers, input/revision types, sampled text construction and a pure refresh planner. The CLI receives an explicit three-provider reader catalog; it does not reference the full app adapter catalog and then filter it after linking. The app keeps all 17 provider entries, order, runtime factories, lazy appearance and telemetry wiring. Its three extracted readers use compatibility forwarders; other providers retain their present adapters. App and CLI compile the same shared reader/policy implementation; SwiftPM package-access interfaces expose only the DTOs and operations the executable needs. If shared files use actual package declarations while Xcode compiles them directly, configure a matching package identity or isolate package-facing wrappers; validate both build paths. Foundation, SQLite, CryptoKit and the existing libzstd dependency are allowed; UI frameworks, telemetry execution and app-owned caches are not core dependencies. Inject host context instead of inferring a legitimate CLI from a bundle ID or relying on mutable global startup ordering.

**Root scopes.** A scope is a versioned hash of provider plus the normalized configured logical root set and discovery-inclusion policy. Normalize aliases through physical path/file identity where available; inaccessible roots remain unknown, never authoritative empty. Keep backend selection/revision within a scope so a file-to-SQLite transition has explicit replacement semantics. Return scopeID, recordID and the optional providerSessionID separately. The cache uses `(scopeID, recordID)` for session identity and `(scopeID, logicalInputKey)` for input ownership; the app's global session_id/path keys are not copied into this schema. A root-set change selects a different namespace and leaves previous scope data inactive and retained. Queries use only their configured active scopes. A reference from another scope is rejected with a scope mismatch unless the caller supplies its corresponding root configuration. Each root inside a logical scope carries separate completeness/authority, so an unreadable archive subroot cannot be retired by a successful primary-root scan.

**Conflicting identities within one scope.** Resolve all inputs claiming one identity before publishing a replacement for it. Proven physical aliases or provider-defined representations of the same logical input may coalesce. Otherwise, duplicate provider IDs from distinct logical inputs produce IDENTITY_CONFLICT: preserve the prior confirmed row and ownership, mark the affected scope partial, return nonzero, and grant no deletion authority for the conflicted ownership. Apply the same rule to ambiguous recordID claims. Never pick a winner by enumeration order, newer timestamp or uniqueness-conflict upsert. If discovery is incomplete and cannot exclude a competing claimant, do not publish an unproven replacement. Confirmed nonconflicting identities in independently complete ownership units may still update. First release rejects ambiguity; exposing divergent copies simultaneously is outside its contract and would require a stable input discriminator in keys and references.

**Identity field mapping.** recordID is the reader's deterministic logical record key; providerSessionID is the provider's optional upstream/resume identifier. Existing path-derived GUI Session.id values are retained in app compatibility adapters, not silently replaced with a provider-ID hint. For Codex/Claude file records, derive recordID from the normalized canonical logical locator; compressed Codex representation changes preserve it. For OpenCode records, derive recordID from its provider ID within the configured scope so a qualified legacy/SQLite transition can preserve it. Keep provider-ID claimant detection separate from record-key construction: distinct locators claiming the same provider ID are still subject to the conflict rule. Histories without an upstream ID can remain readable under locator identity, with resume unavailable. Database lookup uses the providerSessionID; an opaque recordID is validated against the normalized result rather than passed blindly as a database key. Slice 0 pins these mappings in DTO and identity fixtures. Evidence: current `Services/SessionIndexer.swift:2461-2478`, `Services/ClaudeSessionParser.swift:145-166`, `Services/OpenCodeSessionParser.swift:138-165,227-254`.

| Provider | Default root policy | Explicit `--root` policy |
| --- | --- | --- |
| Codex | Resolve CODEX_HOME or ~/.codex; include its sessions and archived_sessions as two declared owned roots. | Value names a sessions directory; scan only that directory. Repeat the option to include an archive directory deliberately; never add an outside sibling automatically. |
| Claude Code | Resolve declared CLAUDE_CONFIG_DIRS/CLAUDE_CONFIG_DIR roots, or ~/.claude when none is configured; scan their projects layout. Desktop/Cowork and unrelated ~/.claude* sibling roots are outside the initial CLI scope. | Value names one config root or projects directory; scan only the normalized projects subtree or supplied directory. Set includeDesktopRoots false in the CLI adapter. |
| OpenCode | Resolve the provider's standard data root and documented layout; choose legacy or SQLite through the current detector. | Accept a data root, legacy storage/session layout, or opencode.db file, normalize to the owning data scope, and report the chosen backend. No fallback to another home root when the explicit root fails. |

These are new CLI scope rules, not changes to the GUI discovery defaults. Provider environment support must be traced and tested rather than assumed; where a current detector lacks an injected setting, add that seam explicitly. Preserve all provider-required metadata/sidecars within the declared scope. The sources response lists the effective roots and policies, so consumers can reproduce the same scope.

**CLI cache store.** Implement a dedicated small CLIIndexStore rather than modifying every app table. Use owned metadata for application/cache ID, schema version, parser/search format versions, scope configuration, last attempt and last successful refresh. Keep normalized sessions, inputs/ownership, sampled FTS text and scoped refresh status; no usage tables. Share pure text/revision policy and appropriate low-level SQLite helpers with the app, not its migrations. `openExistingReadOnly` never bootstraps or changes pragmas/journal mode. `openOwnedForIndex` creates a new marked CLI cache or validates ownership/version before any migration. Reject foreign or newer-schema databases, including symlink/hard-link aliases to app/provider stores; check file identity, not only path strings. Older owned schemas migrate transactionally only during index; an unsupported older schema returns a rebuild instruction and is left intact. Rebuild prepares a coherent new owned cache and retains a coherent previous generation for recovery. Filesystem replacement is allowed only under the exclusive quiescent cutover contract below, never merely because the writer lock was acquired.

One OS-released writer lock per canonical cache covers discovery through reconciliation/publication; a second index returns CACHE_BUSY with no partial write. Readers use short consistent transactions. Persist successful ownership/deletions and success status together; record failed attempts separately. Per-session confirmed writes may become visible during a long refresh, with the attempt still explicitly running/partial and the previous success marker unchanged. No-write means no creation, migration or logical mutation; document unavoidable SQLite WAL bookkeeping and fail explicitly where read-only WAL cannot operate. Never mark a changing provider database immutable. Preserve the app's current test-host database isolation and cleanup bookkeeping when extracting common SQLite helpers.

**SQLite-safe rebuild cutover.** Every cache open holds a shared connection-lifetime lease until its SQLite connection closes, not just until its read transaction ends. Rebuild also owns the writer lock, blocks new opens for cutover, closes its own old-generation connections, and waits boundedly for every existing connection lease to end. Timeout returns CACHE_BUSY and leaves the current cache intact. Only an exclusive replacement phase may checkpoint/close the SQLite generation and complete its sidecar lifecycle, then install the already verified and closed candidate. Never rename over an open database or copy a main database file while ignoring its WAL. Candidate and recovery copy must each be coherent SQLite states. Ordinary queries remain concurrent with ordinary indexing transactions; exclusive cutover is only for replacement/migration operations requiring quiescence.

Replacement coordination uses a stable identity outside the replaced database inode and is consistent across accepted aliases. Resolve symlinks to the canonical cache; reject a hard-link or other alias if the same coordination identity cannot be established. New opens during pending cutover wait boundedly or return CACHE_BUSY. Before/after-replacement interruption recovery runs under the same coordination and verifies generation/ownership before reopening; it must not mix previous-generation journal/WAL/SHM with the replacement. No daemon or generation service is needed. Evidence: current `Indexing/DB.swift:148-163,186-189`; SQLite documents the pathname/sidecar hazard in [database corruption causes, sections 2.5-2.6](https://sqlite.org/howtocorrupt.html) and [WAL lifecycle](https://sqlite.org/wal.html).

**Read snapshots and revision tokens.** Produce normalized events and the revision from the same selected inputs. SQLite session/message/part reads run inside one read transaction. File/multi-file adapters collect a bounded input snapshot, preserve canonical logical locators, verify physical selection and the complete relevant input set before/after collection, and retry once within the deadline or fail HISTORY_CHANGED when it moves. Parse the captured bytes and metadata rather than rereading live sidecars halfway through normalization. Multi-file stability is an optimistic check, not an invented provider-wide atomic transaction. The opaque versioned token hashes source scope, recordID and optional providerSessionID, normalization version, selected backend/representation, relevant input bytes/metadata, and event-order-affecting options. Same-size/coarse-time writes must change the token; main database file stats alone are insufficient. An offset greater than zero requires the previous token. Mismatch fails before a page; nextOffset is exactly offset + returnedEvents, is null at the end, and otherwise advances. Representation changes may conservatively invalidate a token without changing Codex logical identity. No timestamp fallback based on the current clock enters deterministic event identity or tokens.

**Foreground indexing and search.** Explicit CLI indexing bypasses the app's 120-second quiet period and 15/45-minute re-ingest cooldowns. Share an explicit foreground policy with zero quiet/cooldown delays; defer only a genuinely moving, failed or over-budget input and report it. Search exposes sampled candidate snippets from indexed text, with coverage, index revision/time and source refresh status. Event attribution is null until read supplies exact events; FTS snippets are not fabricated event citations. Use deterministic ordering with a scoped-identity tie-breaker. Evidence: `Search/SearchIngestService.swift:232-240,262-270,461-519`; `Search/SessionSearchTextBuilder.swift:164-167,204-247,295-338`.

## Phase one interface decisions

Public executable: `agent-sessions`; retain `as-core` only as an internal migration/build name if needed, not a second supported user contract. `as` is unavailable as a product name because it collides with the assembler. JSONL is the default data format; help/version are documented exceptions. Commands: `sources`, `index`, `list`, `search`, `read`, and `resume` (plan output only). `show`, `parse` and `scan` may remain internal developer tools; an unbounded transcript endpoint is not the default agent workflow.

`sources` describes capabilities, qualification and effective root policy per source. Phase-one defaults include Codex, Claude Code and OpenCode; an explicitly requested unsupported source fails before cache writes. App enablement preferences do not control the CLI. Root precedence is explicit `--root SOURCE=/absolute/path`, then the provider's supported environment settings, then the provider's standard home location, using the bounded root rules above. Configure the context independently; do not use the CLI's `.standard` UserDefaults to read or mutate app preferences. No `--root` is treated as an authentication-home override for resume. A supported resume plan must carry separately verified provider configuration/environment; imported histories without it are not claimed resumable.

Cache: `--db` overrides `AS_CORE_DB`, otherwise macOS uses `~/Library/Application Support/AgentSessionsCLI/index.db`. The dedicated ownership/open-mode rules above apply even to an explicit override. Missing-cache list/search return a structured INDEX_MISSING error and indexing instruction; they do not create a cache. History is never rewritten; cache rebuild must not delete source files or another scope's data. Public responses distinguish scopeID, recordID and optional providerSessionID; the app compatibility layer retains its existing Session.id.

`read` preserves the companion's defaults: 50 events, at most 200, 4096 UTF-8 bytes per content field with an explicit maximum of 65536. Use an 8 MiB serialized page ceiling, counting the header, escaped records, separators and terminal summary. Return fewer complete event records when needed; never skip an event or return a non-progressing page. A single record that cannot fit fails explicitly at that offset. Include source, scopeID, recordID, optional providerSessionID, logical path, event ID/index, explicit truncation and `contentTrust: untrusted_history`. Continuation requires the token contract above; independently full-parsing each captured bounded session remains acceptable. Do not claim streaming parse, durable cursors or automatic secret redaction.

Resource prototype contract: timeout is per read/per-session indexing job, defaults to 30 seconds and is explicitly adjustable to 300; it is not a timeout for an entire first index. Prototype with a 64 MiB cumulative decoded-input budget (adjustable up to 512 MiB), 8 MiB maximum decoded record and 100,000 normalized events per session. Count every relevant file/sidecar/SQLite field, retain stricter existing source limits and fail typed on exhaustion. These are provisional numeric settings to qualify on a representative corpus before the protocol/release freeze, not established ordinary-history capacity. The release must publish the measured settings and expected large-history limitations. Observe resident memory during qualification; remove the submitted draft's unsupported hard 1 GiB RSS guarantee.

Use one job at a time. Where readers cannot cooperatively stop, re-execute the same binary as one internal worker, not a daemon or pool. Drain bounded stdout and stderr concurrently, handle pipe backpressure, terminate/reap with an escalation path on timeout/cancellation/parent disconnect, and release a public success page only after valid worker output, successful termination and EOF. Worker crash is a typed failure. Index can retain safe complete sessions from a partial run, but cannot certify failed scopes for deletion or advance their success marker. All budget enforcement must operate before unbounded line/string/event accumulation, not only after a parser has allocated its full result.

Search returns bounded candidate snippets/coverage, source/scope/path/recordID, optional providerSessionID and index freshness, plus an explicit result limit indicator. Exact event citations come from read. Pagination beyond a bounded top set and exhaustive transcript search are not phase-one promises. `resume` returns executable, argument array, working directory, required environment overrides and a separately quoted display command. It does not launch an agent, shell or GUI. Validate supported CLI capabilities before claiming an executable resume plan; extract a typed command model from validated strategy inputs in the current builders, then render the display shell string from that model. Never recover argv by parsing a display string or shell fallback chain. Preserve verified configuration/environment behavior. No commands in history are executed. Use tagged Codable response DTOs and terminal summaries; serialization failure is an explicit error, never `{}`.
