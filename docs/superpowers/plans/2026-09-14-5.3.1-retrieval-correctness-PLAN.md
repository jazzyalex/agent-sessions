# Agent Sessions 5.3.1 retrieval-correctness plan

_2026-09-14. Target: `main` at `637fc0ce6278f7b09cd4638c1d6c75caff6c4506`. Plan only; no implementation, commit, push, release, or publication is authorized by this document._

## Decision

Ship a focused 5.3.1 correctness patch for five reproduced retrieval defects:

1. reconcile Antigravity disk state after a non-empty cache hydration;
2. refresh an active search when the indexed session set changes;
3. make the title shown in a row searchable immediately;
4. remove Codex transport/scaffolding text from fallback titles;
5. make the existing project filter select one exact project identity instead of a substring.

This is not the broader 5.4 retrieval redesign. It adds no date filter, filter panel, all-source polling, AI summary, title-provenance schema, general CPU project, feature flag, or release work. Free-text `repo:` and `path:` operators retain their current fuzzy semantics; only the project selected from a row or context menu becomes exact.

Implementation is delegated in bounded, sequential packets through the `opencode-free-workers` skill. The parent Codex task owns the design, repository state, integration, independent checks, and final verdict.

## Evidence and current contracts

### Confirmed defects

- `SessionIndexingEngine.hydrateOrScan` returns `.hydrated` as soon as a non-empty cache is available, before `discoverFiles` runs (`AgentSessions/Services/SessionIndexingEngine.swift:116-127`). `AntigravitySessionIndexer` accepts that result and returns ready (`AgentSessions/Services/AntigravitySessionIndexer.swift:168-184`). A new or deleted Antigravity file therefore has no reconciliation path on that launch.
- Search starts with a snapshot of `unified.allSessions` (`AgentSessions/Views/UnifiedSessionsView.swift:4549-4559`). `SearchCoordinator.start` correctly invalidates older work with `runID` (`AgentSessions/Search/SearchCoordinator.swift:191-203`), but normal provider aggregation does not replay an active query when `allSessions` changes.
- Rows display `Session.listTitle` and the Claude archive override (`AgentSessions/Views/UnifiedSessionsView.swift:1035-1039`, `:4252-4255`), while fallback filtering and instant-index text use `Session.title` (`AgentSessions/Services/FilterEngine.swift:656`, `AgentSessions/Search/SessionSearchTextBuilder.swift:235`). Search currency is based on storage revision, not a side-channel title mutation (`AgentSessions/Indexing/DB.swift:2210-2263`). Live 5.3 reproduced an exact displayed-title miss; the current local index had 1,404/5,418 current FTS rows without the effective displayed title, including 1,369/2,170 Codex rows.
- Codex state fallback extraction accepts `first_user_message` material in `SessionIndexer` (`AgentSessions/Services/SessionIndexer.swift:1724-1806`, `:1828-1867`). The current local index had 44 effective Codex titles containing known scaffolding markers; 30 contained attachment-wrapper markers.
- A UI project selection is stored as a `String?` (`AgentSessions/Services/UnifiedSessionIndexer.swift:332`) and fed into the same substring field as `repo:`. In memory, `FilterEngine` uses case-insensitive `contains` (`AgentSessions/Services/FilterEngine.swift:610-613`); SQLite helpers use `LIKE '%value%'` (`AgentSessions/Indexing/DB.swift:1089`, `:2412`, `:2519`, `:2693`). Selecting `app` can therefore include `mobile-app`, `app-server`, and `happy-client`. The current local index had 45 directional substring collisions, with the worst match admitting 5,081 unrelated rows.

### Existing behavior to preserve

- The table keeps its current visual project label and optional worktree suffix. Worktrees already normalize toward a base project in `ProjectPathNormalizer` (`AgentSessions/Model/Session.swift:1295-1815`).
- Explicit query operators remain user-authored fuzzy search. A selected UI project is a separate structured filter and must not be converted into query text.
- Search remains progressively rendered and cancellable. A refresh must not let an old run append into a new result set; the existing `runID` gate remains authoritative.
- Explicit source titles and user renames remain byte-for-byte authoritative. Sanitization applies only to Codex fallback material.
- SQLite search tables and existing user session data remain compatible. This patch should not require a schema migration or a whole-corpus reindex.

## Phase 0: lock the two contracts before editing

The parent task verifies these decisions in the current checkout and records any necessary correction before the first worker runs.

### 0A. Project identity contract

Introduce a structured selection value with separate display and match fields, conceptually:

```swift
struct ProjectSelection: Equatable, Sendable {
    let displayName: String
    let canonicalIdentity: String
    let disambiguationPath: String?
}
```

The exact names are implementation details. The contract is:

- `displayName` is what rows and the badge show;
- `canonicalIdentity` is what matching compares with equality;
- `disambiguationPath` is shown only when two visible projects have the same display name.

Identity rules, in order:

1. A recognized worktree uses a structurally or metadata-proven canonical base checkout path, so the base checkout and its worktrees remain one project.
2. A normal path-backed session uses the standardized project-root path, preserving case according to the platform's path semantics.
3. If a visible row has only a stored repository label and no safe identity, do not offer the exact “Filter by Project” action for that row. Basename equality is not a safe fallback.
4. Desktop virtual-chat classifications remain distinct non-project categories; Phase 0 must decide whether their existing action should be hidden or represented by an explicit virtual identity.
5. Two unrelated directories with the same basename have different identities and receive a shortened parent-path discriminator in the active badge/menu text.
6. Git-origin equality alone does not collapse two independent clones. Worktree collapsing must be proved from the worktree/base path, not inferred from a matching remote.

Extend `ProjectPathNormalizer` to expose the root/identity decision it already makes for names and worktree labels. Do not duplicate its heuristics in the view or filter engine. Add a pure test seam so tests never depend on the user's real filesystem.

Legacy `ProjectFilter` in `UserDefaults` is ephemeral UI state, not data. On first read after this change, resolve an old stored string only if exactly one current safe project identity has that display name; otherwise clear it. Do not silently choose among duplicate or label-only names. No SQLite migration is needed.

### 0B. Effective searchable-title contract

Define one cheap metadata title used by both row display and metadata search:

1. Claude archive title override when the caller has that sidecar value;
2. `customTitle`;
3. authoritative `lightweightTitle`;
4. first usable user text;
5. existing assistant/tool fallback;
6. `No prompt`.

The model-level form is `Session.listTitle`; the Claude sidecar override remains a caller-provided overlay because it is not part of `Session`. Do not make high-frequency search invoke the heavier `Session.title` preamble logic.

For correctness without a reindex, every non-empty query must union cheap in-memory matches of the current effective row title with FTS results before publishing. Pass the current per-session displayed-title snapshot into search rather than changing FTS currency or relying on future reingestion. FTS remains an optimization, not the authority for mutable side-channel titles.

Acceptance gate for Phase 0: tests can construct two same-name projects, a base checkout plus worktree, a label-only session, a renamed byte-current Codex session, and a Claude sidecar title without touching production data.

## Phase 1: Antigravity reconciliation

### Change

Keep `SessionIndexingEngine.hydrateOrScan` unchanged. Add an Antigravity-owned membership reconciliation path that, after `.hydrated`:

1. hydrates the cached rows;
2. discovers the current Antigravity file set once;
3. retains hydrated rows whose storage identity is still present;
4. parses only newly discovered files through the existing lightweight parser and persistence callback;
5. removes cached rows whose files disappeared;
6. returns one deterministically sorted merged result and truthful progress totals.

Do not turn this into a full parse, modified-file refresh redesign, monitor expansion, or synchronous main-thread scan. Verify the existing stale-preview/modified-file ownership in Phase 0 and leave it intact. Cancellation and `refreshToken` checks must guard discovery, parsing, and publication.

## Phase 3: Codex fallback-title cleanup and title-search parity

### 3A. Conservative Codex fallback sanitizer

Before editing, turn the redacted local findings into a small fixture inventory of exact, complete marker shapes. Then add a pure sanitizer at the point where Codex state `first_user_message` is accepted as a fallback title. It may unwrap only recognized leading transport/control structures proved by that inventory, including the applicable forms of:

- the pasted/attached-file wrapper header and its path metadata;
- leading system/developer/app-context/permissions blocks;
- known session/environment scaffolding tags.

It must preserve ordinary angle-bracket text, Markdown, code, paths mentioned by the user, non-English text, malformed/unclosed wrappers, marker-looking text after legitimate content, and explicit custom/source titles. After removing complete recognized leading blocks, trim/collapse whitespace and use the first remaining user-authored content. If nothing remains, return no fallback and continue through the existing title chain; never expose a half-stripped wrapper. Retain the current 512-character state read bound unless an observed fixture proves it cuts off the real prompt.

### 3B. Search the effective displayed title

1. Change cheap metadata fallback matching from `session.title` to `session.listTitle`.
2. At search start, provide a snapshot of the effective titles the table would display, including the Claude archive override.
3. In `SearchCoordinator`, compute current cheap displayed-title matches from metadata-filtered candidates and union them with ranked FTS IDs with stable deduplication. Publish those matches even when the FTS row is byte-current and lacks the side-channel title.
4. Preserve source/date/model/project/archive filtering before the title union. Preserve the FTS order for FTS hits; define a deterministic placement for title-only hits, preferably current session-list order before background/deep appends.
5. Include the Claude archive display override through the existing sidecar overlay or an injected title provider. Do not write archive titles into session files or broaden the database schema.

## Phase 4: active-search freshness

### Change

Add one monotonically increasing dataset revision at the point where `UnifiedSessionIndexer` accepts a structurally new aggregate `allSessions` membership. Compute the signature from stable `(source, sessionID)` membership, not deep `Session` equality, mtime, events, file size, title changes, provider progress, or re-publication of the same rows. The search view/coordinator records the revision used for the current request.

When the revision changes and the trimmed query is non-empty:

1. coalesce provider bursts with the existing search debouncer or a dedicated short debounce;
2. restart the same current query, structured filters, allowed sources, and deep-scan intent against the latest `allSessions` snapshot;
3. let `SearchCoordinator.start` issue a new `runID`, cancelling older current/deep work;
4. preserve the current results during this same-query replacement instead of flashing an empty list, then publish only the newest run;
5. retain the selected session if its ID is still present in the replacement result, otherwise use the existing selection fallback;
6. do nothing when search is empty, the revision did not change, the app is inactive, or only search progress/results changed.

Do not observe raw array equality in the SwiftUI body and do not restart on every progress tick. Generalize or retire the existing `#side`-only dataset restart so there is one coalesced mechanism. Title-only metadata changes are handled by the effective-title snapshot on the next user search; they do not count as indexed-session arrival/removal in 5.3.1.

## Risks and defer triggers

| Risk | Containment | Defer when |
|---|---|---|
| Project identity cannot be derived for a provider | hide the unsafe exact-filter action for that row; never fall back to basename equality | exact selection would exclude valid rows from the same proven project with no stable join key |
| Worktree normalization groups unrelated paths | root identity tests must cover marker, sibling, numbered, and nested worktrees | the current heuristics cannot expose a stable base path without new persistent metadata |
| FTS result limit hides exact-project matches | prefilter by candidate IDs or widen only for structured selection | correctness requires an unbounded DB scan or schema migration not justified for 5.3.1 |
| Title union adds typing latency | scan only cheap current metadata and benchmark at the observed ~5.7K corpus | measured search latency regresses materially; then design an explicit title-revision key rather than ship stale search |
| Search replay storms during provider bursts | membership-only dataset revision, coalesced restart, and existing `runID` gate | deterministic tests cannot bound restarts, prevent empty-result flashing, or block stale publications |
| Antigravity reconciliation becomes a full launch scan | diff cheap file identities and parse only newly discovered rows | the source cannot provide a cheap stable membership check and launch cost regresses materially |
| Sanitizer removes real user text | recognize exact wrappers only; preserve unknown syntax | a fixture demonstrates destructive ambiguity—leave that wrapper unsanitized and narrow the rule |

Each item is independently rollbackable. Do not make the five fixes depend on a database migration or feature flag. If one hits its defer condition, remove only that item, document the evidence, and keep the remaining verified corrections reviewable.
